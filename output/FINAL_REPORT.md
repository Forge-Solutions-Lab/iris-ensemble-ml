# รายงานการทดลอง: Heterogeneous Ensemble บน Iris Dataset (Bagging vs. Boosting)

## 1. Executive Summary

การทดลองนี้เอา Classifier ต่างตระกูล 5 ตัว ได้แก่ k-NN, Decision Tree, Naive Bayes, SVM และ MLP มารวมกันเป็น "สภาโหวต" แล้วเทียบ 2 เทคนิค

- **Bagging**: แต่ละโมเดลเทรนบน bootstrap sample ของตัวเอง ทั้ง 5 โมเดลรันขนานกันด้วย `ThreadPoolExecutor` แล้วหาคำตอบด้วย Majority Voting ที่เขียนด้วย NumPy
- **Boosting**: เทรนโมเดลทีละตัวตามลำดับแบบ AdaBoost ทุกรอบจะเพิ่มน้ำหนักให้ข้อมูลที่ทายผิด และให้น้ำหนักเสียงโหวตของแต่ละโมเดลตามค่า alpha

ผลลัพธ์หลัก

- Bagging และ Boosting ได้ Accuracy บน Test Set **96.67%** (ถูก 29 จาก 30) เท่ากันทั้งคู่ เท่ากับโมเดลเดี่ยวส่วนใหญ่ แต่ต่ำกว่า k-NN และ MLP ที่ได้ 100%
- การรัน Bagging แบบขนานใช้เวลา **82.41 ms** ส่วนแบบตามลำดับใช้ **81.99 ms** ถือว่าเท่ากันภายในความคลาดเคลื่อนของการวัด เพราะเวลาเกือบทั้งหมดอยู่ที่ MLP (79.80 ms) ตัวเดียว
- Boosting ใช้เวลา **160.66 ms** ช้าที่สุด เพราะต้องรอโมเดลก่อนหน้าเสร็จก่อนทุกรอบ และ MLP ต้องเทรนบนข้อมูลที่ resample ตามน้ำหนัก

Iris เป็นข้อมูลขนาดเล็กที่แยกคลาสได้ง่าย Ensemble จึงแทบไม่มีที่ให้ปรับปรุง Accuracy ได้อีก ผลการทดลองนี้ใช้ดูกลไกการทำงานของแต่ละเทคนิคได้ดี แต่ยังไม่พอจะสรุปว่าวิธีไหนแม่นกว่ากัน

## 2. Methodology & Architecture

### 2.1 สมาชิกสภาโหวต 5 ตระกูล

| โมเดล | ตระกูล | หลักการ | การตั้งค่า |
|---|---|---|---|
| k-NN | Distance-based | ทายคลาสจากเสียงข้างมากของเพื่อนบ้านที่ใกล้ที่สุด k ตัว | `n_neighbors=5` |
| Decision Tree | Rule-based / White-box | แบ่งข้อมูลเป็นกฎ if-else ตามฟีเจอร์ที่ลด impurity ได้มากที่สุด | `max_depth=3` |
| Naive Bayes | Probabilistic | ใช้ Bayes' theorem และสมมติว่าฟีเจอร์เป็นอิสระต่อกันและแจกแจงแบบ Gaussian | ค่าเริ่มต้น |
| SVM | Margin-based | หา hyperplane ที่มี margin กว้างที่สุด โดยใช้ RBF kernel แยกข้อมูลแบบไม่เป็นเส้นตรง | `kernel="rbf"` |
| MLP | Neural Network / Black-box | โครงข่ายประสาทเทียม 1 hidden layer เรียนรู้ด้วย backpropagation | `hidden_layer_sizes=(10,)`, `max_iter=2000` |

ฟีเจอร์ทุกตัวผ่าน `StandardScaler` ที่ fit บน Train Set เท่านั้น เพราะ k-NN, SVM และ MLP ไวต่อสเกลของข้อมูล การ scale ไม่มีผลกับ Decision Tree และ Naive Bayes

### 2.2 Bagging: สภาโหวตแบบขนาน

1. สุ่ม bootstrap sample ขนาด 120 แถว (สุ่มแบบใส่คืน) ให้แต่ละโมเดลคนละชุด
2. ส่งงาน fit + predict ทั้ง 5 โมเดลเข้า `ThreadPoolExecutor(max_workers=5)` ให้รันพร้อมกัน
3. รวมผลทำนายเป็น Prediction Matrix ขนาด `(5, 30)` (5 โมเดล x 30 ตัวอย่างทดสอบ)
4. นับเสียงในแต่ละคอลัมน์ด้วย `np.bincount` แล้วเลือกคลาสที่ได้เสียงมากที่สุดด้วย `np.argmax` ถ้าคะแนนเท่ากันจะเลือกคลาสที่มีหมายเลขน้อยกว่า

### 2.3 Boosting: แก้จุดผิดพลาดสะสมตามลำดับ

1. เริ่มให้น้ำหนักข้อมูลทุกแถวเท่ากัน คือ w_i = 1/N
2. วนเทรนโมเดลทีละตัว Decision Tree, Naive Bayes และ SVM รับ `sample_weight` ได้โดยตรง ส่วน k-NN และ MLP รับไม่ได้ จึงใช้วิธีสุ่มข้อมูลใหม่ (resampling) ตามความน่าจะเป็น w_i แทน
3. คำนวณ weighted error e_m = ผลรวมของ w_i ในแถวที่ทายผิดบน Train Set ทั้งชุด
4. คำนวณน้ำหนักโมเดล alpha_m = 0.5 x ln((1 - e_m) / e_m)
5. อัปเดตน้ำหนัก: แถวที่ทายผิดคูณด้วย exp(alpha_m) แถวที่ทายถูกคูณด้วย exp(-alpha_m) แล้ว normalize ให้ผลรวมเป็น 1
6. ตอนทำนาย Test Set แต่ละโมเดลบวกคะแนน alpha_m ให้คลาสที่ตัวเองทาย คลาสที่ได้คะแนนรวมสูงสุดคือคำตอบ

มีกรณีพิเศษ 2 กรณี ถ้า e_m = 0 จะถูก clip เป็น 1e-10 เพื่อไม่ให้หารด้วยศูนย์ และถ้า e_m >= 0.5 จะข้ามโมเดลนั้น เพราะ alpha จะเป็นศูนย์หรือติดลบ สูตร alpha ข้างบนมาจาก AdaBoost แบบ 2 คลาส สำหรับปัญหา 3 คลาส เกณฑ์ e_m < 0.5 จึงเข้มกว่าที่จำเป็น (SAMME ที่ออกแบบมาสำหรับหลายคลาสยอมให้ e_m สูงได้ถึง 2/3) ในการทดลองนี้ไม่มีโมเดลไหนถูกข้าม

## 5. In-depth Analysis & Discussion

### 5.1 Parallel Bagging: เวลาและการลด Variance

**เวลา** ตามทฤษฎี ถ้ารันตามลำดับ เวลารวมจะประมาณผลรวมของเวลาทุกโมเดล แต่ถ้ารันขนาน เวลารวมจะประมาณเวลาของโมเดลที่ช้าที่สุด ในการทดลองนี้ MLP ใช้เวลาประมาณ 80 ms ขณะที่อีก 4 ตัวรวมกันใช้ไม่ถึง 1.5 ms ผลรวมกับค่าสูงสุดจึงแทบเท่ากัน การรันขนานเลยประหยัดเวลาไม่ได้ (82.41 ms เทียบกับ 81.99 ms) นอกจากนี้ Python thread ยังติด GIL และมีค่าใช้จ่ายในการสร้าง thread pool ด้วย

การรันขนานจะคุ้มเมื่อเป็นกรณีเหล่านี้

- สมาชิกแต่ละตัวใช้เวลาใกล้เคียงกันและนานพอ เช่น ข้อมูลใหญ่ขึ้นหรือโมเดลซับซ้อนขึ้น เวลารวมจะลดลงได้เกือบ 5 เท่าเมื่อมี 5 โมเดล
- งานส่วนใหญ่อยู่ในโค้ด C/BLAS ที่ปล่อย GIL (NumPy และ solver หลายตัวของ scikit-learn) หรือใช้ `ProcessPoolExecutor` เพื่อเลี่ยง GIL ไปเลย
- จำนวนสมาชิกในสภาเพิ่มขึ้น เช่น Bagging ที่ใช้โมเดลหลายสิบตัว

เพราะฉะนั้นข้อสรุปว่า "Parallel Computing ช่วยประหยัดเวลา" ถูกต้องในหลักการ แต่ข้อมูลระดับ Iris ไม่ได้แสดงผลนั้นออกมา ตัวเลขที่วัดได้จริงในรายงานนี้คือเวลาเท่ากัน

**Variance** Bagging ลด variance ได้เพราะแต่ละโมเดลเห็นข้อมูลคนละชุดจาก bootstrap ความผิดพลาดที่เกิดจากข้อมูลบางแถว (เช่น outlier) จึงไม่ซ้ำกันทุกโมเดล และการโหวตช่วยหักล้างความผิดพลาดเหล่านั้น ในการทดลองนี้ k-NN ที่เทรนบน bootstrap sample ได้ Accuracy ลดลงเหลือ 90% (จาก 100% ตอนเทรนบนข้อมูลเต็ม) แต่สภาโหวตยังได้ 96.67% เพราะสมาชิกอีก 4 ตัวโหวตถูก นี่คือตัวอย่างจริงที่สภาช่วยกันความผิดพลาดของสมาชิกตัวที่อ่อนในรอบนั้น

### 5.2 ข้อดีและข้อจำกัดของ Boosting แบบ Sequential

ข้อดี

- โมเดลรอบหลังโฟกัสไปที่ข้อมูลที่รอบก่อนทายผิดโดยตรง จึงลด bias ได้
- alpha ให้น้ำหนักโมเดลที่แม่นมากกว่า เห็นได้จาก Naive Bayes (e_m = 0.073) ได้ alpha 1.27 ขณะที่ SVM (e_m = 0.465) ได้แค่ 0.07 แทบไม่มีผลต่อการโหวต

ข้อจำกัด

- **รันขนานไม่ได้** เพราะโมเดลรอบที่ m ต้องใช้น้ำหนักจากรอบ m-1 เวลาจึงเท่ากับผลรวมของทุกรอบ (160.66 ms ช้าที่สุดในตาราง)
- **ลำดับมีผล** SVM อยู่รอบที่ 4 จึงเจอข้อมูลที่น้ำหนักกระจุกอยู่ในแถวที่ยากซึ่ง 3 โมเดลก่อนหน้าทายผิด e_m จึงสูงถึง 0.465 ทั้งที่ SVM เดี่ยวได้ 96.67% ถ้าสลับลำดับ ผลก็จะเปลี่ยน
- **ไวต่อ noise และ outlier** แถวที่ติดป้ายผิดจะถูกเพิ่มน้ำหนักซ้ำทุกรอบ
- **โมเดลที่ไม่รองรับ `sample_weight`** (k-NN, MLP) ต้องใช้ resampling ทำให้มีความสุ่มเพิ่มขึ้น และสื่อน้ำหนักได้ไม่ละเอียดเท่าการส่งน้ำหนักเข้าไปตรง ๆ
- สูตร alpha แบบ 2 คลาสเข้มเกินไปสำหรับปัญหา 3 คลาส ตามที่อธิบายไว้ในข้อ 2.3

### 5.3 ความหลากหลายของ Classifiers (Heterogeneous Diversity)

Ensemble จะได้ประโยชน์ก็ต่อเมื่อสมาชิก "ผิดไม่เหมือนกัน" การใช้ 5 ตระกูลที่มองข้อมูลต่างกัน (ระยะทาง, กฎ, ความน่าจะเป็น, margin, neural network) ช่วยสร้างความหลากหลายนี้ เห็นได้จากโมเดลเดี่ยวที่เทรนบนข้อมูลเต็ม

- Decision Tree และ Naive Bayes ทายผิดตัวอย่างเดียวกัน (index 25 ใน Test Set: versicolor ถูกทายเป็น virginica)
- SVM ทายผิดอีกตัวอย่างหนึ่ง (index 23)
- k-NN และ MLP ไม่ผิดเลย

ใน Bagging สมาชิกมีความเห็นไม่ตรงกันใน 4 จาก 30 ตัวอย่าง ทั้ง Bagging และ Boosting ผิดที่ตัวอย่าง index 25 เหมือนกัน เพราะตัวอย่างนี้อยู่ตรงรอยต่อระหว่าง versicolor กับ virginica และสมาชิกส่วนใหญ่ทายผิดในทิศทางเดียวกัน แสดงให้เห็นข้อจำกัดของการโหวต คือถ้าเสียงข้างมากผิดพร้อมกัน สภาก็จะผิดตาม ความหลากหลายจึงช่วยได้เฉพาะความผิดพลาดที่ไม่สัมพันธ์กันเท่านั้น

## 6. Conclusion & Recommendations

1. บน Iris ทั้ง Bagging และ Boosting ได้ Accuracy 96.67% เท่ากับโมเดลเดี่ยวส่วนใหญ่ ข้อมูลที่เล็กและแยกง่ายทำให้ Ensemble แทบไม่มีที่ให้ปรับปรุง และ Test Set ที่มีแค่ 30 แถวทำให้ผิด 1 ตัวต่าง 3.33% ซึ่งหยาบเกินกว่าจะใช้แยกความแตกต่างระหว่างวิธีได้
2. Parallel Bagging ประหยัดเวลาได้เมื่อสมาชิกใช้เวลาใกล้เคียงกันและนานพอ ในการทดลองนี้ MLP กินเวลาเกือบทั้งหมด การรันขนานจึงไม่ได้เร็วขึ้น เวลาของสภาแบบขนานจะถูกจำกัดด้วยสมาชิกที่ช้าที่สุดเสมอ
3. Boosting เหมาะกับงานที่ต้องการลด bias และมีข้อมูลสะอาด แต่แลกกับการที่รันขนานไม่ได้และไวต่อลำดับโมเดลกับ noise
4. ข้อเสนอแนะสำหรับงานจริง
   - ประเมินด้วย Stratified k-fold Cross-Validation แทนการแบ่ง 80/20 ครั้งเดียว เพื่อให้ได้ค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐานของ Accuracy
   - ทดลองกับข้อมูลที่ใหญ่และยากขึ้น ถึงจะเห็นผลของ Ensemble และ Parallel Computing ชัด
   - ถ้าโมเดลเป็น pure Python หรือถือ GIL ให้ใช้ `ProcessPoolExecutor` แทน thread
   - สำหรับปัญหาหลายคลาส ให้ใช้ alpha แบบ SAMME: alpha = ln((1 - e) / e) + ln(K - 1)
